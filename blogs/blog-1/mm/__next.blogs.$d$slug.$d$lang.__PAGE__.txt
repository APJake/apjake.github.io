<p>CDG Zig ရဲ့ booking flow ဟာ XML layout တွေ၊ fragment အစုအဝေးတွေနဲ့
ရေးထားတာပါ။ နေရာရွေးတာ၊ ယာဉ်ရွေးတာ၊ ဈေးနှုန်းအတည်ပြုတာ၊ driver
ကို map ပေါ်မှာ ကြည့်တာ — screen တိုင်းက သပ်သပ်စီ သီးခြားဖြစ်နေပါတယ်။
UI code ထပ်နေတာတွေ အများကြီးရှိပြီး screen တွေက လိုအပ်တာထက်
ပိုကြာပြီး render ဖြစ်နေပါတယ်။</p>
<h2>ဘာကြောင့် ရွှေ့ခဲ့တာလဲ</h2>
<p>အကြောင်းရင်း နှစ်ခုရှိပါတယ်။ ပထမတစ်ခုက booking flow ဟာ app
တစ်ခုလုံးမှာ အသုံးအများဆုံး screen ဖြစ်တာပါ။ ဒုတိယတစ်ခုက ကျွန်တော်တို့
ထပ်ထည့်ချင်တဲ့ screen အသစ်တွေ (multi-stop ride၊ fare estimate) တွေက
layout အဟောင်းနဲ့ အဆင်မပြေဘဲ XML ကို ညှိနေရတာ ဖြစ်ပါတယ်။</p>
<blockquote>
<p>Compose ကို ရွေးချယ်ရတာ XML ညံ့လို့ မဟုတ်ပါဘူး — booking state
ကို UI အဖြစ် ဖတ်လို့ရတဲ့အခါ state-driven UI က booking object
နဲ့ ပိုကိုက်ညီတာပါ။</p>
</blockquote>
<h2>ဘာတွေ ပြင်ခဲ့သလဲ</h2>
<ul>
<li>Booking flow အတွက် <code>Fragment</code> ငါးခုကို <code>NavHost</code> တစ်ခုနဲ့
<code>Composable</code> screen တွေအစုအဝေးတစ်ခုနဲ့ အစားထိုးခဲ့ပါတယ်။</li>
<li>မျှဝေသုံးတဲ့ အပိုင်းတွေ (date picker၊ payment row၊ address card)
ကို app ရဲ့ ကျန်အပိုင်းတွေ သုံးနေတဲ့ library ထဲ ထည့်ခဲ့ပါတယ်။</li>
<li>Map ကို <code>MapView</code> ကနေ Compose interop layer အသစ်ပြောင်းခဲ့ပြီး

</ul>
