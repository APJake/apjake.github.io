3:Te32,<h1>Offline အလုပ်လုပ်တဲ့ အကြွေးစာရင်း app (Jar Gyi)</h1>
<p>Jar Gyi ကို စရေးခဲ့တုန်းက ကျွန်တော် သိချင်တာက ရိုးရိုးရှင်းရှင်းပါပဲ —
မြန်မာပြည်မှာ လူတွေ အကြွေးတွေ မှတ်ထားတဲ့အခါ network မရှိဘဲ
အလုပ်လုပ်နိုင်တဲ့ app လိုအပ်တယ်။ Google account မလိုဘူး။ Sync မလိုဘူး။
Offline မှာ အကုန်လုံး အလုပ်လုပ်ရမယ်။</p>
<h2>Architecture ရွေးချယ်မှု</h2>
<ul>
<li><strong>Room</strong> — local database၊ SQLite ပေါ်မှာ type-safe abstraction</li>
<li><strong>DataStore</strong> — preferences အတွက် (currency, theme)</li>
<li><strong>ViewModel + Flow</strong> — reactive UI</li>
<li><strong>No account, no analytics</strong> — privacy policy မှာ ရေးထားသလိုပါပဲ</li>
</ul>
<p>Network module မလိုအပ်ပါဘူး။ Firebase မလိုအပ်ပါဘူး။ Crash reporting
က Crashlytics ပဲ သုံးပါတယ်။ ဒါက app ရဲ့ အဓိက design decision ပါ —
ရိုးရှင်းမှုက အဓိပ္ပါယ်ရှိတယ်။</p>
<h2>Data model</h2>
<pre><code class="language-kotlin">@Entity(tableName = "debts")
data class Debt(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val personName: String,
    val amount: Long,
    val type: DebtType,        // LENT or BORROWED
    val note: String?,
    val createdAt: Long,
    val dueDate: Long?
)
</code></pre>
<p><code>DebtType</code> က <code>LENT</code> (ငါဟာ ပေးထားတယ်) နဲ့ <code>BORROWED</code> (ငါဟာ ယူထားတယ်)
နှစ်မျိုးပါ။ ယာင်ယာ တစ်ဖက်က ငါ့ကို ပေးရမှာ ဖြစ်တယ်ဆိုရင် <code>BORROWED</code>။
ငါက ယာင်ယာ တစ်ဖက်ကို ပေးထားတယ်ဆိုရင် <code>LENT</code>။</p>
<h2>UI ရေးထုံး</h2>
<p>Compose ကို သုံးပါတယ်။ Material 3၊ list တွေအတွက် <code>LazyColumn</code>၊
debt အသစ်ထည့်တာက <code>BottomSheet</code>။ Flow နဲ့ reactive — debt list ပြောင်းရင်
UI အလိုအလျောက် update ဖြစ်ပါတယ်။</p>
<h2>ဘာကြောင့် account မလိုအပ်တာလဲ</h2>
<p>ကျွန်တော်တို့ ပြောချင်တာ — လူတွေ ကိုယ့်ရဲ့ ငွေကြေးအခြေအနေကို
Google account နဲ့ ချိတ်စေချင်တာ မဟုတ်ဘူး။ Local-only app က
ပိုလုံခြုံပြီး ပိုရိုးရှင်းပါတယ်။ Backup လိုအပ်ရင် manual export/import
JSON နဲ့ လုပ်နိုင်ပါတယ်။</p>
